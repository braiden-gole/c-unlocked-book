Chapter 2: Primitive Types & Memory Layout

Unlike high-level languages that abstract memory management, C forces you to confront the exact byte width, binary representation, and hardware storage layout of every data type.

2.1 Fundamental Integer & Floating-Point Types

The C standard guarantees minimum sizing requirements rather than absolute byte widths across all target architectures. A char is guaranteed to be at least 8 bits, an int matches the natural word size of the processor architecture, and standard floats conform to IEEE-754 specifications.

Data Type Minimum Size (Bytes) Typical Range
char 1 byte -128 to 127 (or 0 to 255 unsigned)
short int 2 bytes -32,768 to 32,767
int 4 bytes -2,147,483,648 to 2,147,483,647
long long 8 bytes -9.22 quintillion to +9.22 quintillion
float 4 bytes ~7 digits of precision (IEEE-754)
double 8 bytes ~15-17 digits of precision (IEEE-754)

2.2 Determining Sizing Dynamically via sizeof

Because type widths can vary across 32-bit, 64-bit, and embedded microcontrollers, C provides the compile-time sizeof operator to query exact memory footprints.

#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    // Query exact byte allocation sizes using the sizeof operator.
    size_t character_size = sizeof(char);
    size_t integer_size = sizeof(int);
    size_t integer_pointer_size = sizeof(int*);

    // Safely print memory characteristics to standard output.
    int number_of_characters_printed = printf("Memory Sizing Report:\n"
        " - char size: %zu byte(s)\n"
        " - int size: %zu byte(s)\n"
        " - pointer size: %zu byte(s)\n", character_size, integer_size, integer_pointer_size);

    if (number_of_characters_printed < 0)
    {
        fprintf(stderr, "Error: Failed to write output stream.\n");

        return EXIT_FAILURE;
    }

    return EXIT_SUCCESS;
}

2.3 The Role of size_t in Array Sizing

When working with arrays and memory buffers, you will frequently encounter size_t. Although often conceptualized as a type definition representing the structural memory boundary of objects, size_t is an unsigned integer type guaranteed by the C standard to be large enough to hold the size in bytes of any object or array that can theoretically exist on your target architecture (spanning 32 bits on 32-bit systems and 64 bits on 64-bit systems).

Using size_t for array indexing and loop bounds is critical for robust systems code because it prevents negative-value indexing bugs and eliminates overflow errors when managing massive data buffers.

2.4 Fixed-Width Integers via <stdint.h>

For systems-level programming where exact bit widths are non-negotiable (such as network protocols, file parsers, or hardware register mapping), always rely on fixed-width types:

  • Signed Integers: int8_t, int16_t, int32_t, int64_t
  • Unsigned Integers: uint8_t, uint16_t, uint32_t, uint64_t

2.5 Endianness & Memory Byte Layout

When a multi-byte integer (such as a 32-bit int or 64-bit pointer) is stored in RAM, the order in which its bytes are arranged depends on your CPU architecture's **endianness**:

  • Little-Endian (x86_64, ARM): Stores the Least Significant Byte (LSB) at the lowest memory address. For example, the hexadecimal value 0x12345678 is laid out in memory sequentially as 78 56 34 12.
  • Big-Endian (Network Byte Order, older mainframes): Stores the Most Significant Byte (MSB) at the lowest memory address (12 34 56 78).

We can inspect the active architecture's byte ordering at runtime by casting an integer pointer to a character pointer:

#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>

int main(void)
{
    uint32_t hexadecimal_identifier = 0x00000001;
    
    // Inspect the lowest memory address of the integer via a byte pointer.
    unsigned char* hex_pointer = (unsigned char*)&hexadecimal_identifier;

    if (*hex_pointer == 0x01)
    {
        printf("Architecture Endianness: Little-Endian (LSB stored first).\n");
    }
    else
    {
        printf("Architecture Endianness: Big-Endian (MSB stored first).\n");
    }

    return EXIT_SUCCESS;
}

2.6 Extended Demonstration: Bit Representation and Integer Overflow Behavior

Understanding signed integer storage requires inspecting how numbers wrap around under overflow conditions. The following comprehensive example illustrates fixed-width integer bounds, bit shifting, and signed vs. unsigned overflow semantics:

#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <limits.h>

// Function prototype to inspect individual bits of a byte.
void inspect_byte_bits(uint8_t byte_value);

int main(void)
{
    // 1. Demonstrate unsigned integer wrap-around behavior.
    uint8_t maximum_sensor_count = UINT8_MAX;

    printf("Initial Sensor Count (Max uint8_t): %u\n", maximum_sensor_count);

    // Incrementing past maximum triggers defined unsigned wrap-around to zero.
    maximum_sensor_count++;

    printf("Sensor Count After Overflow Increment: %u\n", maximum_sensor_count);

    // 2. Inspect bit representation of a specific signed value.
    
    // Cast or direct assignment example.
    int8_t signal_amplitude_gain = -12.0f;
    int8_t negative_voltage_reading = -55;

    printf("\nInspecting Bit Pattern for Signed Value: %d\n", negative_voltage_reading);

    inspect_byte_bits((uint8_t)negative_voltage_reading);

    // 3. Demonstrate floating-point precision limitations.
    float standard_precision_pi = 3.14159265358979323846f;
    double high_precision_pi = 3.14159265358979323846;

    printf("\nFloating-Point Precision Comparison:\n");
    printf(" - float representation : %.10f\n", standard_precision_pi);
    printf(" - double representation: %.15lf\n", high_precision_pi);

    return EXIT_SUCCESS;
}

void inspect_byte_bits(uint8_t byte_value)
{
    printf("Binary Representation: ");

    for (int bit_index = 7; bit_index >= 0; bit_index--)
    {
        int extracted_bit = (byte_value >> bit_index) & 1;

        printf("%d", extracted_bit);

        if (bit_index == 4)
        {
            // Nibble visual separator.
            printf(" ");
        }
    }

    printf("\n");
}

2.7 Summary Checklist

  • Never assume int is always 4 bytes across embedded platforms—use <stdint.h> when explicit bit bounds matter.
  • Always use size_t for array counts, indexing, and memory allocation parameters.
  • Use the %zu format specifier when printing sizeof or size_t values to prevent format-string mismatch warnings.
  • Be mindful of system endianness when serializing binary data structures across network interfaces or storage files.
