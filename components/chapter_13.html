Chapter 13: Error Handling & Assertions

Unlike high-level languages equipped with exceptions, standard C handles runtime anomalies through explicit error codes, status enums, pointer validation, operating system error indicators, and runtime assertions. Mastering defensive error propagation and contract validation is paramount for building crash-resistant systems software.

13.1 Explicit Return Codes & Status Enums

Standard C lacks native exception handling constructs like try and catch. Instead, robust systems functions return explicit status indicators such as boolean success flags, integer error codes, or custom enum status types allowing callers to inspect return values immediately and handle failures gracefully.

13.2 Runtime Assertions with <assert.h>

Assertions (provided by the standard library header <assert.h>) enforce internal invariants and programmer assumptions during development and debugging. If an assertion condition evaluates to false (0), the program immediately terminates via abort(), printing diagnostic information to standard error.

Assertions should never be used to validate user input or recoverable runtime failures like out-of-memory errors; they are strictly designed to catch internal logic bugs and violated preconditions.

13.3 System Error Handling with `errno` and `strerror()`

When interacting with operating system calls and standard I/O streams (such as opening files or managing system resources), C sets the global thread-safe variable errno (declared in <errno.h>). Inspecting errno immediately following a failed library call allows developers to translate numeric error codes into human-readable diagnostic strings using strerror().

The following example demonstrates defensive file stream opening with errno error extraction:

#include <stdio.h>
#include <stdlib.h>
#include <errno.h>
#include <string.h>

int main(void)
{
    // Attempt to open a non-existent configuration file in read mode.
    const char* path = "./config/non_existent_settings.conf";

    FILE* configuration_file = fopen(path, "r");

    // Validate file pointer defensively.
    if (configuration_file == NULL)
    {
        // Capture the operating system error code stored in errno.
        int saved_error_code = errno;

        fprintf(stderr, "Error: Failed to open file '%s'. Reason: %s (Errno Code: %d)\n",
                path, strerror(saved_error_code), saved_error_code);

        return EXIT_FAILURE;
    }

    // This block is unreachable in this example.
    fclose(configuration_file);
    
    configuration_file = NULL;

    return EXIT_SUCCESS;
}

13.4 Comprehensive Systems Demonstration: Robust Error Handling & Assertion Engine

The following detailed systems demonstration illustrates combining explicit status enums, defensive pointer checking, and runtime assertions to validate inputs and manage heap allocation errors safely:

#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <stdbool.h>
#include <assert.h>

// Define an enumeration for explicit function status and error codes.
typedef enum 
{
    SYSTEM_STATUS_SUCCESS = 0,
    SYSTEM_ERROR_NULL_POINTER = 1,
    SYSTEM_ERROR_INVALID_CAPACITY = 2,
    SYSTEM_ERROR_ALLOCATION_FAIL = 3
} system_status_t;

// Function prototype utilizing explicit status return codes.
system_status_t allocate_secure_buffer(int32_t** output_addresses, size_t count);

int main(void)
{
    int32_t* secure_data = NULL;

    size_t number_of_items = 10;

    // Invoke function and capture explicit status return code.
    system_status_t status = allocate_secure_buffer(&secure_data, number_of_items);

    if (status != SYSTEM_STATUS_SUCCESS)
    {
        fprintf(stderr, "Error: Secure buffer allocation failed with status code %d.\n", status);

        return EXIT_FAILURE;
    }

    // Use runtime assertion to guarantee pointer validity before processing.
    assert(secure_data != NULL);

    printf("Secure buffer successfully allocated and validated via assertions.\n");

    // Populate buffer elements safely.
    for (size_t index = 0; index < number_of_items; index++)
    {
        secure_data[index] = (int32_t)(index * 100);
    }

    // Safely release allocated memory.
    free(secure_data);

    secure_data = NULL;

    printf("Memory successfully released and error handling sequence completed.\n");

    return EXIT_SUCCESS;
}

system_status_t allocate_secure_buffer(int32_t** output_addresses, size_t count)
{
    // Validate pointer parameters defensively.
    if (output_addresses == NULL)
    {
        return SYSTEM_ERROR_NULL_POINTER;
    }

    // Validate operational bounds defensively.
    if (count == 0)
    {
        return SYSTEM_ERROR_INVALID_CAPACITY;
    }

    // Allocate memory on the heap.
    int32_t* block = (int32_t*)malloc(count * sizeof(int32_t));

    if (block == NULL)
    {
        return SYSTEM_ERROR_ALLOCATION_FAIL;
    }

    // Dereference double pointer to assign allocated block.
    *output_addresses = block;

    return SYSTEM_STATUS_SUCCESS;
}

13.5 Summary Checklist

  • Use explicit status enums or error codes to propagate recoverable runtime failures back to calling routines.
  • Always validate pointer arguments and operational bounds defensively before executing core logic.
  • Inspect errno and translate codes with strerror() when standard library operations fail.
  • Use assert() from <assert.h> to catch internal logic flaws and programmer assumption violations during development.
  • Never use assertions to handle expected or recoverable runtime errors such as network timeouts or missing files.
